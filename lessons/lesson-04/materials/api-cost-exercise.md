# WorkBuddy 练习：为一笔订单调查算模型费用

用时 6 分钟。输入是 [A1024 会话 JSON](../../lesson-01/materials/session-history.json) 的 `teaching_usage.calls`。离线输入总量取自课 1 mock Session，用 Qwen 教学模板复算。缓存命中和输出是教学设定，模拟按 API usage 的口径记账。实际接入时，三类用量均应读取 API 的 usage。案例生产环境采用私有化部署，练习仅用合成订单做离线演算。

费率固定为 DeepSeek `deepseek-flash` 的高峰公开价，2026-11-10 核对。每百万 token 分别为未命中输入 0.30 美元、命中输入 0.006 美元、输出 1.20 美元。课堂用同一档费率来比较，实际账单取决于模型、时段和计费规则。换服务商时换用对应模型返回的 usage 和费率。本练习只算模型 token 费用。 [定价](https://api-docs.deepseek.com/quick_start/pricing/) · [上下文缓存与 usage 字段](https://api-docs.deepseek.com/guides/kv_cache/)

## 给 WorkBuddy 的任务

> 写一个可重复运行的小程序，读入会话 JSON 的 teaching_usage.calls 和三种费率。每行检查 `prompt_tokens = prompt_cache_hit_tokens + prompt_cache_miss_tokens`，用 Decimal 分别计算三项费用。输出每轮、每种计费类别和整笔任务的合计，按任务汇总后再舍入。保持各轮输入、输出的 token 数和费率不变，把所有输入按缓存命中价计费，计算理论最低成本。最后再算所有输入均未命中时的费用。用下方简化任务校验。只做本地计算，无需 API Key。

## 讲师核对

一笔简化的订单调查任务包含三次模型调用。先用这个例子验算计算器。

| 任务事件 | 内容 | 未命中输入 | 命中输入 | 输出 | 模型费用（美元） |
|---|---|---:|---:|---:|---:|
| 用户提交 | 调查一笔订单 | | | | 0 |
| 模型调用 1 | 选择查订单 | 1,000 | 0 | 50 | 0.0003600 |
| 工具执行 | 查订单 | | | | 0 |
| 模型调用 2 | 选择查物流 | 500 | 1,000 | 60 | 0.0002280 |
| 工具执行 | 查物流 | | | | 0 |
| 模型调用 3 | 写答复 | 400 | 1,400 | 150 | 0.0003084 |
| 整单合计 | | | | | **0.0008964** |

用户提交和工具执行在这张表上记 0 模型费用。用户问题、工具调用参数和工具结果分别在相关模型调用的输入或输出中计费。

再核对 A1024 完整教学用量。

| 项目 | 用量 | 费用（美元） |
|---|---:|---:|
| 未命中输入 | 3,109 | 0.000932700 |
| 命中输入 | 9,216 | 0.000055296 |
| 输出 | 380 | 0.000456000 |
| 合计 | 输入 12,325，输出 380 | **0.001443996** |

逐轮费用（美元）：0.000432000、0.000172044、0.000114180、0.000104448、0.000092616、0.000255684、0.000273024。

- **理论最低成本（输入全命中）**　(12,325 × 0.006 + 380 × 1.20) ÷ 1,000,000 = **0.000529950 美元/单**。固定调用次数、各轮输入输出量和费率，全部输入按命中价计算。生产中的命中量以实际 `usage` 为准。
- **输入全未命中**　(12,325 × 0.30 + 380 × 1.20) ÷ 1,000,000 = **0.004153500 美元/单**。

在复测时，若只有离线输入对照，先报告输入变化。课堂可沿用全未命中情景并把输出固定在 380 token。用过滤附录后的 11,117 个输入复算，得到 0.003791100 美元，比同口径的基线少 0.000362400 美元。用真实 API 复测时，以两次运行各自返回的 usage 重算整单，保留失败和重试记录。
